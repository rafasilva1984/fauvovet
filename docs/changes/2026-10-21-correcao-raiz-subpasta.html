FauvoVet — Endereço inicial em /fauvovet + diagnóstico do deploy respondendo 404

ID: 2026-10-21-correcao-raiz-subpasta · Data: 18/10/2026 · Módulo: rotas / publicação · Estado: IMPLEMENTADO E TESTADO LOCALMENTE

1. Objetivo e contexto

Durante a atualização do servidor, o proprietário rodou deploy:remote … diagnostico e recebeu HTTP 404. Para investigar, conferimos o servidor de fora, só com pedidos públicos e sem token:

  • /fauvovet/up → 200, /fauvovet/login → 200 e /fauvovet/painel → 302 para /fauvovet/login: o sistema está no ar.
  • /fauvovet/_deploy/diagnostico → 404 em JSON com os cabeçalhos de segurança do próprio FauvoVet. É a recusa proposital das ferramentas de deploy: elas respondem 404 quando estão desligadas ou o token não confere. Ver a seção 9.
  • Defeito encontrado: http://dradeboragaldino.com.br/fauvovet/ redirecionava para http://dradeboragaldino.com.br/painel, sem o /fauvovet, e caía numa página inexistente do domínio. Quem digitava só o endereço base não chegava ao sistema.

2. O que mudou

  • routes/web.php: Route::redirect('/', '/painel') deu lugar a redirect()->route('dashboard'). O Route::redirect do Laravel gera um caminho relativo ao domínio e descarta a subpasta; o redirecionamento pelo nome da rota mantém o caminho base.
  • tests/Feature/DeployAndHeadersTest.php: novo teste que simula o Apache servindo /fauvovet/index.php e exige o destino http://localhost/fauvovet/painel. Antes da correção, o mesmo teste falhava com '/painel'.
  • Sem migração, sem dependência nova e sem mudança no .env.

Os mesmos do guia anterior (fundos e exames estruturados): PHP 8.3+, Node e pnpm do projeto e MySQL local via pnpm db:start.

Manual, no computador: com pnpm dev, abra a URL base local (http://127.0.0.1:8000/fauvovet/). Ela deve levar a /fauvovet/login, ou a /fauvovet/painel se você já estiver logado.

Na produção, depois de publicar, faça o mesmo em http://dradeboragaldino.com.br/fauvovet.

7. Publicação na Locaweb / FileZilla (se aplicável)

Siga a seção 7 do guia de fundos e exames estruturados, gerando o pacote a partir deste commit. Para destravar o diagnostico que respondeu 404, faça nesta ordem:

  1. Terminal Ubuntu: pnpm deploy:token. Ele mostra um TOKEN e uma linha DEPLOY_TOKEN_SHA256=…, gerados juntos. Use os dois da mesma execução.
  2. FileZilla: no /app-fauvovet/.env, coloque DEPLOY_TOOLS_ENABLED=true e troque a linha DEPLOY_TOKEN_SHA256 pela recém-gerada. Salve e envie de volta. Ao pedir para editar, o FileZilla baixa uma cópia, então confirme o envio quando ele perguntar.
  3. FileZilla: apague /app-fauvovet/bootstrap/cache/config.php. Este é o passo mais esquecido: depois de um otimizar, o Laravel lê esse cache e ignora o .env.
  4. Terminal Ubuntu, no mesmo terminal em que vai rodar o comando: export FAUVOVET_DEPLOY_TOKEN='<TOKEN do passo 1>' e depois FAUVOVET_ALLOW_HTTP=1 pnpm deploy:remote http://dradeboragaldino.com.br/fauvovet diagnostico. Enquanto não houver HTTPS, o token viaja sem criptografia; por isso ele é novo a cada atualização e as ferramentas são desligadas ao final.

8. Backup e rollback

Para reverter só esta correção, reenvie o pacote anterior. Não há migração nem dados envolvidos. O backup do banco antes de migrar continua obrigatório por causa da migração da versão anterior.

9. Troubleshooting

SintomaCausa e solução
diagnostico → HTTP 404 com {"message": ""}O sistema respondeu e recusou de propósito. Há três causas possíveis: (1) DEPLOY_TOOLS_ENABLED não está true no .env do servidor; (2) existe um bootstrap/cache/config.php antigo, gravado quando o flag estava false; (3) o TOKEN exportado não corresponde ao DEPLOY_TOKEN_SHA256, por ser de outra execução do deploy:token, ter um espaço sobrando ou ter sido exportado em outro terminal. Refaça os passos 1 a 4 da seção 7.
HTTP 404 com página HTML da LocawebO endereço está sem /fauvovet, ou o public_html/fauvovet/index.php não está no servidor.
HTTP 429Muitas tentativas seguidas (limite das ferramentas de deploy). Aguarde alguns minutos.
O endereço base leva a /painel sem /fauvovetA versão anterior a esta correção ainda está no servidor.
