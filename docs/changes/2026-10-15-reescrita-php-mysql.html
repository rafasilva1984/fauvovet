Reescrita para PHP 8 + Laravel 13 + MySQL, com isolamento multi-tenant em camadas

ID: 2026-10-15-reescrita-php-mysql · Data: 15/10/2026 · Versão: 0.2.0 · Módulos: A. Tenants, §5 Isolamento, §7 UI, §9 Deploy · Estado: implementado e testado localmente; deploy na Locaweb ainda não executado

1. Objetivo e contexto

O plano contratado é Hospedagem Dedicada Locaweb 4 GB, só painel, sem SSH, com MySQL. A stack anterior (NestJS + Next.js + PostgreSQL com RLS) exigia Node.js persistente e PostgreSQL, que esse plano não oferece. A pedido do proprietário, a aplicação foi reescrita em PHP/Laravel + MySQL, seguindo o modelo de outro projeto dele já operado na Locaweb (Node só para compilar CSS/JS localmente; deploy por FTP), sem perder o isolamento entre clínicas (ADR-010).

Critério de aceite: todas as funcionalidades da fundação anterior funcionando na nova stack; isolamento entre duas clínicas provado em cada camada; pacote de deploy ensaiado em modo produção (migração e caches via HTTP, sem terminal); pnpm verify --e2e verde.

2. O que mudou

Removido (permanece no histórico do Git, commits 7d303af e 4a9ade7): apps/api (NestJS), apps/web (Next.js), packages/contracts, scripts do PostgreSQL embutido.

Adicionado:

  • Laravel 13.36 na raiz (PHP ≥ 8.3; config.platform.php=8.3.0 → Symfony 7.4 LTS, para o vendor/ rodar em 8.3–8.5).
  • Isolamento (app/Tenancy): TenantContext, TenantScope + BelongsToTenant (falha fechada), TenantOwned, TenantQueryFirewall (antes de cada SQL), Roles; middlewares ResolveTenant (antes do route model binding), RequirePermission, SecurityHeaders (CSP com nonce), RequestContext, PreventRequestForgery (sem cookie XSRF), DeployRateLimit.
  • Migrações MySQL 5.7+: 2026_10_15_000001_create_identity_tables (users, sessions, cache, jobs) e 2026_10_15_000002_create_tenancy_tables (tenants, units, memberships, membership_units com FKs compostas, tenant_themes, audit_events).
  • Telas (Blade + Alpine build CSP + Tailwind 4): login, cadastro PF/PJ, escolha de clínica/unidade, painel por função, unidades (lista/criação/detalhe), equipe, aparência, erros 403/404/419/429/500/503 em pt-BR.
  • Deploy sem SSH: deploy/public/index.php + .htaccess, deploy/env.production.example, endpoints /_deploy/diagnostico|migrar|otimizar (flag + token SHA-256 + limite em arquivo), scripts deploy:package, deploy:token, deploy:remote, smoke.
  • Ambiente local sem root: scripts/local-mysql.mjs (Percona Server 5.7.44 com SHA-256 conferido, libaio e pdo_mysql extraídos dos pacotes do Ubuntu), scripts/php.mjs, scripts/dev-router.php (imita /fauvovet).
  • Qualidade: PHPUnit (55 testes), Larastan nível 6, Pint, Prettier, composer audit, Playwright (14 cenários × 2 dispositivos), benchmark, CI com PHP 8.3.

Falhas encontradas e corrigidas pelos testes nesta reescrita: (1) cor da clínica não aparecia na tela — o CSS base sobrescrevia o tema (achado pelo E2E); (2) dados de layout de uma clínica reaproveitados na requisição seguinte em processo persistente (achado pelo teste de isolamento; corrigido com reset por requisição e memo amarrado à clínica); (3) ID de outra clínica na URL respondia 302 em vez de 404 (escopo rodava antes da clínica ativa); (4) ferramentas de deploy quebravam antes da 1ª migração (rate limit dependia da tabela cache); (5) IDs do seed inválidos como ULID; (6) verify injetava o .env de desenvolvimento nos testes — a guarda *_test recusou, como projetado.

3. Pré-requisitos (WSL2 e Git Bash)

  • PHP 8.3+ com mbstring, intl, sodium (verificado: 8.5.4). pdo_mysql: extraído automaticamente no Ubuntu/Debian ou sudo apt install php8.x-mysql.
  • Composer 2 (verificado: 2.10.3). Node 24 + pnpm 12.4.2 só para build/testes.
  • MySQL: opcional — pnpm bootstrap baixa Percona 5.7 (~86 MB) para .data/, porta 33079, só 127.0.0.1.
  • Portas: 33079 (MySQL), 8000 (dev), 8100 (E2E), 8300 (benchmark).
  • Variáveis: .env.example (valores fictícios). Produção: deploy/env.production.example.

Git Bash/macOS: NOT RUN. O MySQL automático é só Linux x86_64; nesses ambientes use MySQL próprio e pnpm bootstrap --external-db.

4. Passo a passo para aplicar a mudança

Instalação nova ou existente (a stack mudou: trate como nova)

git pull --ff-only
rm -rf node_modules apps packages          # restos da stack anterior, se existirem
pnpm bootstrap                             # composer, pnpm, APP_KEY, MySQL local, migrações, seed, build
pnpm dev                                   # http://127.0.0.1:8000/fauvovet

Resultado esperado do bootstrap: Bancos fauvovet_dev, fauvovet_test ... prontos, Seed fictício: 2 clínicas, 3 unidades, 6 usuários e Ambiente pronto. O PostgreSQL local antigo (.data/pg) não é mais usado e pode ser apagado.

Deploy na Locaweb

Passo a passo completo e numerado em docs/DEPLOY_LOCAWEB.md (pacote, FileZilla, .env no servidor, deploy:remote diagnostico → migrar → otimizar, criação da 1ª clínica, desligar ferramentas, smoke).

Manual (senha = SEED_PASSWORD do .env)

  1. ana.titular@aurora.exemplo.test → escolha “Aurora — Centro” → painel de gestão; Unidades → crie uma; Aparência → #808080 bloqueia o salvar, #1d4e89 salva e a cor muda na tela.
  2. bruno.vet@… → menu só com Painel e Unidades; abrir /fauvovet/equipe → 403.
  3. diana.titular@horizonte.exemplo.test → só “Atendimento domiciliar”; abrir /fauvovet/unidades/01K7FV000000000000000TNA01 (unidade da Aurora) → 404.
  4. eva.plantonista@exemplo.test → troca entre as duas clínicas; nada se mistura.
  5. No celular (ou DevTools): barra inferior, menu ☰ com “Trocar clínica/unidade” e “Sair”.

Tentativas que DEVEM falhar (todas cobertas por teste)

  • tenant_id de outra clínica em formulário, URL ou cabeçalho → ignorado; dado gravado na clínica da sessão.
  • Consulta sem clínica ativa → bloqueada. DB::table('units')->get(), withoutGlobalScopes(), SQL bruto, filtro com ID de outra clínica → bloqueados pelo firewall.
  • Vincular unidade de B a vínculo de A no banco → erro de FK composta.
  • POST sem token CSRF → 419; ferramentas de deploy sem token → 404; 6ª tentativa/min → 429.
  • Senha errada 10× → bloqueio temporário; 11 tentativas no mesmo e-mail → 429.

7. Publicação na Locaweb / FileZilla (se aplicável)

Compatível com o plano informado (PHP + MySQL, sem SSH). Ainda não publicado: aguarda a versão do PHP no painel (≥ 8.3), os dados do MySQL e a verificação de HTTPS. Procedimento completo em docs/DEPLOY_LOCAWEB.md; resumo:

pnpm verify --e2e
pnpm deploy:package        # .deploy/fauvovet-<versão>/{app-fauvovet, public_html/fauvovet}
pnpm deploy:token          # token (gerenciador de senhas) + DEPLOY_TOKEN_SHA256 (.env do servidor)
# FileZilla (SFTP/FTPS): app-fauvovet/ → raiz do FTP ; public_html/fauvovet/ → public_html/fauvovet/
export FAUVOVET_DEPLOY_TOKEN='...'
pnpm deploy:remote https://dradeboragaldino.com.br/fauvovet diagnostico
pnpm deploy:remote https://dradeboragaldino.com.br/fauvovet migrar
pnpm deploy:remote https://dradeboragaldino.com.br/fauvovet otimizar
SMOKE_URL=https://dradeboragaldino.com.br/fauvovet pnpm smoke

Ensaio realizado (simulação fiel em .data/prodsim: pacote real, index.php de produção apontando para ../../app-fauvovet, APP_ENV=production, APP_DEBUG=false, banco vazio): diagnóstico 200 (PHP 8.5.4, nenhuma extensão faltando, 2 migrações pendentes) → migrar 200 → otimizar (config/route/view cache = 0) → cadastro 302 para o painel → pnpm smoke 6/6 PASS → nenhum arquivo de log de erro. Limitação: o servidor do ensaio não lê .htaccess; as regras do Apache serão verificadas no primeiro deploy real.

Sem HTTPS: apenas teste com dados fictícios; SESSION_SECURE_COOKIE=true e certificado ativo são obrigatórios antes de qualquer dado real.

8. Backup e rollback

  • Código: git revert deste commit volta à stack Node/PostgreSQL anterior (que não roda na hospedagem atual). No servidor, rollback = reenviar o pacote .deploy/ da versão anterior (guarde cada pacote publicado).
  • Banco: migrações são forward-only. Antes de qualquer deploy com migração nova, faça backup pelo painel; reverter = restaurar o backup.
  • Local: dados fictícios e recriáveis. Para recomeçar: pnpm db:stop, mover .data/mysql para fora do projeto e pnpm db:setup && pnpm db:migrate && pnpm db:seed.
  • Emergência em produção: renomear public_html/fauvovet/index.php pelo FileZilla.

9. Troubleshooting

SintomaCausa / ação
pdo_mysql ausente / could not find driverRode pnpm db:setup (extrai a extensão) e use os comandos via pnpm/node scripts/php.mjs; ou instale php8.x-mysql.
Testes recusados: banco "fauvovet_dev" / migrate:fresh recusadoGuarda de segurança: algo injetou DB_DATABASE de desenvolvimento. Rode pelos comandos do projeto.
Página com Bloqueado pelo firewall de clínicas no log (tenant_firewall_blocked)Consulta em tabela de clínica sem escopo — use o model com BelongsToTenant; não use SQL bruto.
E2E “Já existe um servidor”Encerre o processo na porta 8100 (ss -ltnp | grep 8100).
Deploy: 500 em tudo antes de migrarNormal (tabelas sessions/cache ausentes). Rode deploy:remote … migrar.
diagnostico 404Ferramentas desligadas, token errado, ou cache de configuração antigo: apague app-fauvovet/bootstrap/cache/config.php.

Limitações conhecidas: sem RLS — firewall heurístico (risco aceito, documentado); sem MFA/recuperação de senha/convites; backup automático não configurado; HTTPS do domínio não verificado.
